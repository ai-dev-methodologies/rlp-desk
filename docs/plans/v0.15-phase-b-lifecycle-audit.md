**Race-window narrative** (the gap B2-FIX closes):
1. Worker writes `done-claim.json` (announcing completion intent).
2. Worker is supposed to follow up by writing `iter-signal.json` (the actual handshake).
3. Today: nothing kills the worker pane between step 1 and step 2. The TUI returns to its idle prompt and may continue self-review for 30-120s before emitting iter-signal — or worse, may revise/overwrite done-claim mid-flight.
4. Bug #5 (worker-dead-on-reuse) and Bug #7 (post-sentinel race) both manifest here. Bug #8 mitigations rely on done-claim being a stable artifact, which today it is not.

## §4 — Table 3: Phase 0 baseline distribution

> **Status: SYNTHETIC (Option C).** This audit ships analytical estimates derived from the leader's own sleep/timeout constants in source, **not** empirical samples from a sandbox campaign. The estimates are sufficient to seed B3 tolerance bands at first-cut conservatism (`band = max(p95 × 2, fixed floor)` per plan v3 §B3 AC3.5). Plan v3 §B3 pre-merge band revalidation against a fresh 5-iter B4 sample (after B4 ships its real helper) is **mandatory** and is the empirical replacement step. Until then, treat the bands as upper-bound proxies — too loose, not too tight.

### §4.1 — Method (Option C — analytical / non-empirical)

The original plan v3 §B1 Phase 0 prescribed a throwaway-instrumentation sandbox campaign. Operator selected **Option C** (synthetic baseline) on 2026-05-07 to avoid:
- LLM token spend on a non-substrate measurement run
- Branch hygiene risk of authoring + reverting a throwaway patch on the audit-doc branch
- Wall-clock cost (30-60min) on the critical path before B2-FIX

In place of empirical sampling, baselines are derived from **substrate constants observed in source** at the freeze SHA in §7. Each metric is an upper-bound estimate parameterized by the loops/timeouts that actually govern it. Where the zsh leader and Node leader diverge (zsh signal-poll cadence is 5s; Node is 100ms), the **zsh number is taken as the baseline** because the zsh path is the production default for `--mode tmux` campaigns (the only mode Phase B targets).

### §4.2 — Baseline distribution (analytical estimates)

| Metric name | p50 (ms) | p95 (ms) | p99 (ms) | Derivation |
|---|---:|---:|---:|---|
| `iter_signal_write_to_read_ms` | 2500 | 4750 | 4950 | Uniform-arrival model over `POLL_INTERVAL=5s` (zsh:53). Worker write occurs at random offset within a leader sleep window. p50 = window/2 = 2500ms; p95 = window × 0.95 = 4750ms; p99 = window × 0.99 = 4950ms. Node leader at `pollIntervalMs=100ms` (signal-poller.mjs:123) yields p50 ~50ms / p95 ~95ms — provided here for completeness but **not** the band source. |
| `verdict_write_to_read_ms` | 2500 | 4750 | 4950 | Same uniform-arrival model — Verifier feeds the same `poll_for_signal` loop on `VERDICT_FILE` (run_ralph_desk.zsh:2545). |
| `pane_eof_to_cleanup_ms` | 1000 | 2500 | 5000 | `_kill_pane_process` issues C-c, sleeps 0.5s, issues C-c, sleeps 1s, then `wait_for_pane_ready 5` (lib_ralph_desk.zsh:264-269 / pane-manager.mjs:108-115). Best case (TUI exits on first C-c): ~500ms. Median (second C-c needed, shell prompt observed within next loop): ~1000ms. p95 (TUI hangs through both C-c, exits before timeout): ~2500ms. p99 = `exitTimeoutMs` ceiling = 5000ms. |
| `pane_reap_latency_ms` | 4000 | 8000 | 10000 | This metric is unmeasurable pre-B2-FIX (no done-claim reap site exists). Estimate uses **proxy = `iter_signal_write_to_read_ms` p* + `pane_eof_to_cleanup_ms` p\*** because the post-B2-FIX semantics are "leader observes done-claim → leader runs `_kill_pane_process` → leader confirms shell". p50 = 2500 + 1000 = 3500 → rounded to 4000ms safety. p95 = 4750 + 2500 = 7250 → rounded to 8000ms. p99 = 4950 + 5000 = 9950 → rounded to 10000ms. **Plan v3 §B3 pre-merge revalidation against real B4 sample is non-optional for this metric.** |
| `sentinel_lock_to_unlock_ms` (per type) | iter-signal: 300000 / verdict: 120000 / done-claim: post-B2-FIX TBD | iter-signal: 900000 / verdict: 480000 / done-claim: TBD | iter-signal: 1800000 / verdict: 900000 / done-claim: TBD | Lock applied at observation; unlock applied only on operator-recovery (`_unlock_sentinel` at run_ralph_desk.zsh:3102-3103). For successful iterations the file stays locked from observation to end-of-iter archival (lib_ralph_desk.zsh:596-602). p50 ≈ typical iter wallclock for the role (Worker iters ≈ 5min ≈ 300000ms; Verifier turnaround ≈ 2min ≈ 120000ms). p95 / p99 follow long-tail iters with prompt-stall escalation. done-claim has no production data point pre-B2-FIX. |

### §4.3 — Calibration intent (no patch reference, by Option C selection)

Because no throwaway patch was authored:
- Patch diff: **none** — `git diff main..HEAD --stat` will show only `docs/plans/v0.15-phase-b-lifecycle-audit.md` (the only change in this PR).
- Discard step: not applicable.

The numbers above are bounded by source-visible constants and are intended to be **replaced**, not relied upon, once B4 ships:

1. After PR-B4 lands, run a 5-iter sandbox campaign with the **real** B4 helper enabled (`RLP_LIFECYCLE_METRICS=1`).
2. Compute p50/p95/p99 from `~/.claude/ralph-desk/analytics/<slug>/campaign.jsonl` per metric.
3. If empirical p95 differs by >25% from the Option-C number above, **edit this audit doc in a follow-up commit** and re-derive B3 tolerance bands. Plan v3 §B3 pre-merge revalidation owns this gate.
4. Until that revalidation happens, B3 must NOT merge with hard value assertions.

### §4.4 — Why Option C is acceptable here (deviation justification)

- **Plan v3 §B3 already requires pre-merge revalidation.** Synthetic numbers in B1 do not silently bake into a release; they hit a hard gate before B3 ships.
- **The zsh `POLL_INTERVAL=5s` ceiling is the dominant term** for the two metrics that drive B3 release-blocking assertions (`iter_signal_write_to_read_ms`, `verdict_write_to_read_ms`). That constant is in source — synthetic and empirical agree on the ceiling, and disagree only on the within-window distribution shape (uniform vs. real LLM jitter), which `band = p95 × 2` absorbs easily.
- **Bug #4 lesson respected**: Option B (skip Phase 0 entirely, defer to B3) would have moved a measurement gate inside the assertion-strengthening PR — exactly the bundling pattern Option A in the ADR rejects. Option C preserves the substrate-vs-verification cleavage while admitting up front that the numbers are placeholders.
- **AC1.3 wording**: "Phase 0 baseline distribution captured + provenance (patch + command + discard)". Operator's Option C selection narrows "captured" to "analytically derived" and renders patch/command/discard inapplicable. This audit explicitly records that deviation — a reviewer can see at a glance that no campaign was run and that B3 owns the empirical refit.
