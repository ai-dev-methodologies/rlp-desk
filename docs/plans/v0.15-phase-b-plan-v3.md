## RALPLAN-DR Summary

### Principles (5)
1. **Hardening only, no new features** — every line traces to Bug #5/6/7/10 or its observability.
2. **Preserve 4 differentiators** — multi-engine consensus, multi-mission queue, BLOCK_TAGS, structured SV reports.
3. **Substrate fix → observability → SV strengthening** — strictly enforced by build order.
4. **One PR per concern** — avoid Bug #4 fix-of-fix bundling pattern.
5. **Real-LLM SV is regression guard** — no fix without bug-N scenario strengthening.

### Drivers (3)
1. Race window minimization across all worker/verifier-produced sentinels (5 types — gap closed in B2-FIX).
2. Test cost discipline ($50 nightly cap; net delta +$1/nightly).
3. CLAUDE.md ABSOLUTE compliance — commit/push/publish gated on user approval.

### Selected: Option A (4 PRs in order **B1 → B2-FIX → B4 → B3**)

### Option labels (stable, consistent)
- **Option A**: 4 separate PRs in build order. Selected.
- **Option B**: 2 PRs (B1+B2-FIX bundled = substrate; B4+B3 bundled = verification). Architect's steelman.
  - Pros: halves codex review cycles; substrate-vs-verification cleavage natural
  - Cons: B2-FIX implements code change AND ships its regression test in same PR — git bisect cannot distinguish "fix bug" from "test bug"
  - Rejected because Option A's bisect granularity is more valuable than 2× review savings on a stabilization track
- **Option C**: 1 monolithic PR.
  - Pros: single review pass; atomic delivery
  - Cons: violates §4 stabilization principle "Increment by category"; Bug #4 lesson — large PRs hide regressions in adjacent code
  - Rejected

**Invariant (scoped per B1 Table 1)**:
> For each sentinel S with Producer ∈ {Worker, Verifier}: lock(0o444) before write && producer pane killed before next phase && partial-flush invisible to leader poll.
> For each sentinel S with Producer = Leader: lock(0o444) only.

**Table cases (8 minimum, 12 target)**:
| # | Sentinel | Producer | Concurrent writer | Expected |
|---|---|---|---|---|
| 1 | iter-signal | Worker | none | locked + readable |
| 2 | iter-signal | Worker | second worker pane attempts overwrite | second blocked, content preserved |
| 3 | verdict | Verifier | none | locked + readable |
| 4 | verdict | Verifier | verifier still emitting tokens after write | pane killed before next iter dispatched |
| 5 | done-claim | Worker | worker pane idling post-write | pane killed within 5s (fixed by B2-FIX code change) |
| 6 | blocked | Leader | partial sidecar.json before .md | poll never sees inconsistent state |
| 7 | blocked | Leader | none | locked, no reaper |
| 8 | complete | Leader | none | locked, no reaper |

tmux stubbed by default; real-tmux variant gated by `RLP_TEST_REAL_TMUX=1`.

**Acceptance criteria**:

## Pre-mortem (3 scenarios, all with concrete mitigations + verifications)

### Scenario 1: B4 metric write itself adds latency masking real race
- **Risk**: synchronous appendFile per-sentinel adds 5-50ms
- **Mitigation 1**: zsh helper async via `( ... ) &` background spawn
- **Mitigation 2**: campaign.jsonl write batched once at end-of-iter, not per-sentinel
- **Mitigation 3**: AC4.2 enforces <2ms/scenario delta
- **Verification**: `time bash tests/sv-gate-fast.sh` before/after, asserted in PR-B4 description

### Scenario 2: B3 real-LLM scenarios flake under LLM non-determinism
- **Risk**: timing assertions fail on slow LLM days
- **Mitigation 1**: Stage 1 (presence) deterministic regardless of LLM latency
- **Mitigation 2**: Stage 2 bands = p95 × 2 from B1 baseline (covers ≥97.5% of distribution)
- **Mitigation 3**: bug-06 structural at $0 — no LLM dependency for that bug class
- **Verification**: AC3.1a 5-run pre-merge sample; AC3.1b 3-night release sample

### Scenario 3: B2-FIX done-claim reaper introduces new race
- **Risk**: extending reaper to done-claim site may introduce a new ordering bug (the kind Bug #7 originally introduced)
- **Mitigation 1**: B2-FIX code change is structurally identical to existing iter-signal reaper invocation (parity-by-construction)
- **Mitigation 2**: B2-FIX invariant test includes case 5 (done-claim worker pane idling) explicitly
- **Mitigation 3**: B3 bug-05 + bug-07 acts as backstop with real LLM
- **Verification**: AC2.1 invariant tests primary; AC2.2 8+ table cases; AC2.4 real-tmux opt-in

## ADR

**Decision**: Adopt Option A (4 separate PRs in order **B1 → B2-FIX → B4 → B3**) for Phase B substrate hardening.

**Drivers**:
1. Race window minimization across all worker/verifier-produced sentinels
2. Test cost discipline ($50 nightly cap)
3. CLAUDE.md ABSOLUTE compliance

**Alternatives considered** (stable labels):
- Option A (4 PRs): selected. Substrate-vs-verification cleavage; bisect granularity.
- Option B (2 PRs, B1+B2-FIX bundled, B4+B3 bundled): rejected. Bisect cannot distinguish "fix" from "test of fix"; ~5% review savings not worth diagnostic loss on stabilization track.
- Option C (1 monolithic PR): rejected. §4 stabilization plan: "Increment by category". Bug #4 lesson on large PRs hiding adjacent regressions.

**Why chosen**: Option A's 4-PR fan-out preserves substrate-vs-verification cleavage for git bisect; reordered B2-FIX before B4 fixes Critic round-1 P1.1 (Principle 3 alignment); feature flag eliminates integration debt; Phase 0 baseline in B1 enables release-blocking value assertions in B3 (round-1 P1.3 fix).

**Consequences**:
- 4 codex review cycles (acceptable)
- B4 ships flag-gated; production opt-in until v0.15.5
- bug-06 structural retained; deterministic injection deferred to PR-B5
- B1 includes a measurement Phase 0 (5-iter sandbox dry-run) — slight scope expansion enables release-blocking B3 ACs

**Follow-ups**:
- PR-B5 (post-Phase-B): deterministic idle-injection for bug-06 real-LLM upgrade
- PR-B6 (post-v0.15.4): flip RLP_LIFECYCLE_METRICS default-on
- PR-B7 (post-v0.15.6): remove RLP_LIFECYCLE_METRICS flag entirely
- Phase C: tolerance band auto-tuning from accumulated B4 production data
