## §1 — CRITICAL findings

### C1 — B3 Stage 2 jq query falsely PASSes when metric never emits
**File**: `tests/sv-real-llm/lib/b3-lifecycle-assertions.sh:65-77`
**Evidence**:
```bash
$ echo '{"lifecycle_metrics":null}' > /tmp/t.jsonl
$ jq -s --arg m "iter_signal_write_to_read_ms" '
    [.[] | (.lifecycle_metrics // {})[$m] // [] | .[].value_ms // 0] | max // 0
  ' /tmp/t.jsonl
0
```
The SKIP guard `[[ -z "$max_observed" || "$max_observed" == "null" ]]` does not fire for `0`. Then `(( 0 <= 6000 ))` returns true → Stage 2 falsely PASSes when B4 telemetry never fired.

**Why critical**: undermines the entire purpose of Stage 2. A regression that disables B4 emission entirely would silently pass the gate.

**Fix** (in b3-lifecycle-assertions.sh):
```bash
# Pre-compute entry count to distinguish "no data" from "zero-valued data"
entry_count=$(jq -s --arg m "$metric" \
  '[.[] | (.lifecycle_metrics // {})[$m] // []] | flatten | length' "$jsonl")
if (( entry_count == 0 )); then
  echo "ASSERT $label SKIP: metric not emitted (zero entries)"
  return 0
fi
# Then compute max from non-empty set, no // 0 sentinel
max_observed=$(jq -s --arg m "$metric" \
  '[.[] | (.lifecycle_metrics // {})[$m] // [] | .[].value_ms] | max' "$jsonl")
```

### H2 — `_sentinelLockTimes` Map: lock-to-unlock for done-claim unmeasurable in happy path
**File**: `src/node/util/lifecycle-metrics.mjs:32, 62, 67-73, 78-` and `src/node/runner/campaign-main-loop.mjs:1947`
**Evidence**:
```bash
$ grep -n "_sentinelLockTimes\|markLockStart\|markUnlock" src/node/util/lifecycle-metrics.mjs
32:    this._sentinelLockTimes = new Map();
62:    this._sentinelLockTimes.set(sentinelType, t);
67:    const start = this._sentinelLockTimes.get(sentinelType);
73:    this._sentinelLockTimes.delete(sentinelType);
```
done-claim lock is applied (markLockStart) but production never calls `unlockSentinelFile(doneClaimFile)` (only signalFile + verdictFile are unlocked at iter start, L1552-1555). So `markUnlock('done-claim.json')` never fires in happy path. The metric `sentinel_lock_to_unlock_ms` for done-claim is structurally unmeasurable.

**Why high**: B3 plan v3 Table 2 lists this metric as "per type" object {type: ms} expecting per-type emission. For done-claim it will never have a value. The B3 jq query (after C1 fix) will SKIP correctly, but the metric was a lie in the plan.

**Fix**: either (a) document done-claim as measure-once-at-archive (lib_ralph_desk.zsh:602 archives but doesn't unlock — could emit metric there), or (b) remove done-claim from sentinel_lock_to_unlock_ms expected emission.

### H3 — markLockStart fires AFTER lockSentinel (timestamp inversion)
**File**: `src/node/runner/campaign-main-loop.mjs:1419-1422, 1946-1947`
**Evidence**:
```
1419:      await lockSentinel(sentinelFile, { log: ... });
1422:      lifecycleMetrics.markLockStart(path.basename(sentinelFile));
...
1946:    await lockSentinel(paths.doneClaimFile, ...);
1947:    lifecycleMetrics.markLockStart('done-claim.json');
```
markLockStart records `Date.now()` AFTER chmod 0o444 has completed. Sentinel-lock-to-unlock metric measures from "post-chmod" rather than "pre-chmod". Skew = chmod execution time = µs-ms.

**Severity rationale**: real bug, but practical impact is sub-millisecond on ms-scale metrics. **HIGH for correctness**, LOW for operational impact.

**Fix**: move `markLockStart` BEFORE `await lockSentinel(...)` at both call sites.

## §3 — MEDIUM findings

### M1 — us006 Bug-7-C contract change semantics (test always provides done-claim)
**File**: `tests/node/us006-campaign-main-loop.test.mjs:738-776`
**Evidence**: amended test asserts `tmux.locked.length == tmux.reaped.length + workerReaps.length` (extra +1 lock per worker reap = done-claim). But the test always pre-creates done-claim files. In production, if a worker doesn't write done-claim (e.g., codex worker exits without calling done-claim writer), `lockSentinel(doneClaimFile)` fail-opens silently — total locks = reaps. The amended assertion would FAIL in that production scenario.

**Why medium**: real production scenario (worker exits without done-claim) hits Bug #8 BLOCKED path which doesn't reach the lockSentinel call site. So practical impact is contained. But the test asserts a contract that doesn't hold in all paths.

**Fix**: add a second test case "worker exits without done-claim" → `tmux.locked.length == tmux.reaped.length`.

### M2 — `log_lifecycle_metric` zsh helper concurrent appender risk
**File**: `src/scripts/lib_ralph_desk.zsh:316`
**Evidence**: `( log_debug "[LIFECYCLE] ..." ) &!` spawns disowned subshell per metric. POSIX guarantees atomic append for writes ≤ PIPE_BUF (4096B); single line ~150B is safe. But multiple concurrent calls (e.g., during rapid iter teardown) could in theory interleave on filesystems that don't honor PIPE_BUF (NFS, FUSE).

**Why medium**: real risk only on non-mainline filesystems. Local SSD on macOS/Linux is fine.

**Fix**: optional — use `flock(1)` wrapper, or document as "best-effort logging on local FS".
