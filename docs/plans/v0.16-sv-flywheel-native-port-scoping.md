## 1. Why this is the next priority

Strategic review (`docs/plans/strategic-review/rlp-desk-strategic-review.md`) confirmed Option B (fundamental redesign — vision held, substrate replaced). Two realities make SV/flywheel port the highest-leverage W2 work:

1. **SV gate is the framework that 10 production bugs passed through** before shipping. Strengthening SV is the single highest leverage move on the central pain ("blueprint to autonomous completion").
2. **SV/flywheel only exists in the Node leader today** (`campaign-main-loop.mjs`, ~2k of the 4.5k Node leader LOC). Until ported to Native Agent() path, P3 deletion (Node leader removal) is blocked.

→ Native port unblocks BOTH the SV strengthening AND the P3 cleanup.

## 3. What "SV / flywheel native port" means

### 3a. SV report — port to Native Agent() leader (slash command)

Today the SV report is a post-campaign analysis emitted by `runFinalSequentialVerify` in `campaign-main-loop.mjs`. It reads:
- All `iter-NNN-done-claim.json` (worker `execution_steps`)
- All `iter-NNN-verify-verdict.json` (verifier `reasoning` × 5 categories)
- `campaign.jsonl` analytics
- `status.json` per-iter cost/duration

It writes:
- `~/.claude/ralph-desk/analytics/<slug>/self-verification-data.json`
- `~/.claude/ralph-desk/analytics/<slug>/self-verification-report-NNN.md`

The slash command (`/rlp-desk run`) ALREADY archives `iter-NNN.{done-claim,verify-verdict}.json` per iteration (rlp-desk.md:564-565). What's missing is the post-campaign aggregator.

**Port surface:**
- New section in `src/commands/rlp-desk.md` Leader Loop: after the COMPLETE sentinel write, if `--with-self-verification` is set, run a final aggregator phase that reads the same archived files and emits the same two analytics artifacts. Implementation in slash-command-resident logic — leader IS the SV runner.
- New helper module `src/node/shared/sv-report.mjs` (~300 LOC estimate) extracted from current `campaign-main-loop.mjs:1100-1400` (rough range — exact extraction at impl time). Used by both Node leader (for backwards compat during transition) and Native Agent() leader (via `Bash("node ~/.claude/ralph-desk/node/shared/sv-report.mjs <slug>")` invocation).
- Tests: existing `tests/test_us008_self_verification_e2e.sh` exercises the contract; fork into a Native Agent()-mode variant that exercises the same contract via slash invocation.

### 3b. Flywheel — port to Native Agent() leader

Flywheel runs BEFORE worker dispatch each iteration: a separate claude/codex agent reviews the campaign's direction (PRD, recent verdicts, consecutive failures) and emits a `flywheel-signal.json` with verdict `pass` (continue) / `fail` (mission abort) / `inconclusive` (retry up to N times).

**Port surface:**
- Slash command Leader Loop §1.5 (NEW, between sentinel check and worker dispatch): if `--flywheel != off`, dispatch a flywheel `Agent(...)` call. Same contract as Node leader's `dispatchFlywheel`.
- Flywheel guard: same pattern — a second agent reviews the flywheel verdict before accepting. Slash dispatches via `Agent(...)` with the guard prompt.
- No new shared module needed — slash command IS the orchestrator. The `flywheel-signal.json` / `flywheel-guard-verdict.json` files stay as the on-disk contract.

### 3c. What stays Node-leader-only (until P3)

- `campaign-main-loop.mjs` itself (the file that orchestrates everything for `--mode agent`).
- `src/node/tmux/`, `src/node/polling/` (tmux pane lifecycle, signal polling — ~2.7k LOC). Used by both Node leader and zsh runner via shared paths. P3 work deletes these together with `--mode tmux` deprecation.

## 5. Open questions (resolve at impl time)

- **Q1**: Native Agent() leader has no timeout API (per Safety Contract §4: long-running → tmux). Does SV aggregator hit timeout for 50+ iter campaigns? Answer: probably not (file reads + summary, not LLM calls). Verify with empirical run.
- **Q2**: Flywheel guard adds 2 extra `Agent(...)` calls per iteration when flywheel is on. Native turn-keepalive must hold across 4 sequential `Agent(...)` calls per iter (flywheel + guard + worker + verifier). Stress test in W3b.
- **Q3**: BOS dev's 19th launch — does it want SV native NOW (forced upgrade) or v0.15.1 → wait → v0.16 stable? Default: backward-compat. Both `--mode agent` (with SV via Node leader) and `--mode native` (no SV until v0.16) work.

## 6. Out of scope

- P2 of native-revert plan: `--mode agent` hard-error + default flip 'agent' → 'tmux'. **Deferred to v0.17 or later** because it breaks external wrappers and the scoping doc above doesn't yet have a migration guide. This branch's banner countdown sets expectation; actual hard-error needs the migration guide first.
- P3 of native-revert plan: Node leader deletion (~4.5k LOC). **Blocked on P2 + 19th launch end + 1-2 weeks of v0.16 production validation**. Earliest: v0.18 or v1.0.0.
- Real-LLM SV gate (vs current grep+unit-test labeling). **Separate workstream**, but deeply complementary — strategic review names this as the real fix to "10 bugs passed SV gate". Tracked as a separate v0.18 candidate.
