> **Status**: FROZEN. Original scoping doc reduced to historical reference.

## TL;DR — Why This Plan Is Frozen

`plan-ceo-review` direct-read of `omc` (oh-my-claudecode) skills established that:

| omc skill | Covers rlp-desk vision item |
|---|---|
| `/oh-my-claudecode:autopilot` | Phase 0 (analyst+architect) → Phase 1 (plan+critic) → Phase 2 (ralph+ultrawork) → Phase 3 (ultraqa) → Phase 4 (validate) — ENTIRE end-to-end blueprint completion |
| `/oh-my-claudecode:ralph` | PRD-driven persistence loop, prd.json scaffold + auto-refinement, tier-aware delegation, mandatory deslop pass, regression re-verification |
| `/oh-my-claudecode:team` | N coordinated agents via Claude Code native team tools, staged pipeline (team-plan → team-prd → team-exec → team-verify → team-fix) |
| `/oh-my-claudecode:ralplan` | Planner → Architect → Critic consensus (used in this very session) |

Coverage is **~95%** of the original rlp-desk vision, not the 80% earlier estimates suggested.

The v0.16.0 redesign would have spent 8 weeks porting SV/flywheel to Native Agent() and deleting ~4.5k LOC of Node leader infrastructure. That work would land **after** omc already provides the same capabilities. The opportunity cost — BOS dev's actual product work delayed for an additional 8 weeks plus 4-8 weeks of post-redesign stabilization — exceeds any plausible gain.

## What rlp-desk Differentiates (Real, Small)

Direct comparison after Option B would have completed:

| Feature | rlp-desk has | omc has | Differentiation real? |
|---|---|---|---|
| Multi-engine parallel consensus per iteration (claude+codex simultaneously) | ✅ `--consensus all` | ❌ (single critic via `--critic=codex`) | YES, real but niche |
| Multi-mission queue + cross-mission analytics | ✅ `RLP_BACKGROUND=1` | ❌ (single-task) | YES, real but niche |
| BLOCK_TAGS P1-D failure taxonomy | ✅ rich `reason_category × recoverable × suggested_action` | ❌ (verdict pass/fail/blocked) | YES, but small |
| Self-Verification report aggregator | ✅ structured `self-verification-report-NNN.md` | ❌ (lighter `progress.txt`) | YES, but small |

These 4 differentiators amount to ~200-500 LOC of unique value. Maintaining 9,000+ LOC of substrate to deliver 5% differentiation is not a defensible economic ratio.

## Original Scoping Reference (intent that was abandoned)

The original W2-W4 plan was to:

1. Extract `src/node/shared/sv-report.mjs` from `campaign-main-loop.mjs` (the Self-Verification report aggregator that today only runs under Node leader `--mode agent`).
2. Add slash-command-leader invocation paths so `--mode native` campaigns produce the same `~/.claude/ralph-desk/analytics/<slug>/self-verification-report-NNN.md` artifact.
3. Port flywheel direction-review + flywheel-guard dispatch to `--mode native` so the Native Agent() leader has parity with the Node leader.
4. Build out e2e tests for `--mode native` SV + flywheel paths (forks of `tests/test_us008_self_verification_e2e.sh` and similar).
5. Release v0.16.0-rc as the "Native parity" milestone, then delete the Node leader (~4.5k LOC) in P3, then deprecate `--mode tmux` in W5-W8 and ship v1.0.0.

That intent is preserved here so a future reader can reconstruct what we considered. **None of it is being pursued.** omc's `/autopilot` Phase 4 already provides end-of-campaign aggregation; omc's `/ralph` already provides PRD-driven loop with reviewer verification; omc's `/team` already provides multi-agent staged pipelines. Building the same things under the rlp-desk name is duplication, not differentiation.

---

## Closing Note

rlp-desk is a learning project that produced 4 real differentiators (multi-engine parallel consensus, multi-mission queue, BLOCK_TAGS taxonomy, SV report aggregation). Those differentiators belong in a tool people already use (omc). Maintaining a separate substrate to deliver 5% unique value is not engineering, it is ego. This pivot acknowledges that and redirects the work to where it provides leverage.
