# rlp-desk 4차 요청 (개정 3판) — 무인-완주 계획 규칙 명문화 + worktree 격리 + BLOCKED 원인 필드 — 2026-07-20

요청자: tire-plletdata PO 세션. **개정 사유: 초판의 ①②(오너-질의 채널·제자리 재개)는 철회한다** — Ralph loop 컨셉(계약을 완전하게 써서 루프가 사람 없이 완주) 위반이라는 사용자 지적이 맞다. 오늘 발생한 "오너 결정 대기" 6회는 도구 결함이 아니라 **PO의 계약 작성 결함**이었다: 등록 규칙·rebaseline 규칙·합성 데이터 판정은 전부 run 전에 PRD 위임 규칙으로 명시 가능했던 것들이고, 그랬으면 왕복 0회였다. human-in-the-loop 채널을 도구에 넣는 것은 그 결함을 제도화하는 것이므로 요청하지 않는다.

남는 요청은 3건이다. ①이 이번 사건의 근본 재발 방지다.

## 요청 ① 무인-완주 계획 규칙을 brainstorm/init 스킬 규칙으로 명문화 (사용자 확정 지시)

rlp-desk의 brainstorm·init·PRD 작성 단계에 다음 규칙을 **스킬 문서/거버넌스에 명시**해 달라:

> **캠페인 실행 중 사용자/오너 인터랙션은 0이어야 한다. 이를 보장하지 못하는 PRD는 완성이 아니다.**
> 1. 모든 결정은 계획 단계(brainstorm)에서 소진한다 — 캠페인이 만날 결정 부류(신규 표면 등록 관례, 원장/산출물 갱신 규칙, fixture·합성데이터 판정, baseline 처분 등)를 계획 시점에 식별해 **위임 규칙 절**로 PRD에 명시한다.
> 2. PRD·AC에 "오너/사용자 결정 필요 시 멈춘다"류 게이트를 설계하는 것을 금지한다. blocked 정당 사유는 ① 비가역 파괴 ② 계약 자체의 변경 필요 ③ 보호 경로 위반 필요 — 세 가지뿐임을 워커 계약에 명시한다.
> 3. brainstorm 완료 게이트(Ambiguity Gate 옆)에 **무인-완주 점검**을 추가한다: "이 PRD로 루프가 사람 없이 완주 가능한가? 실행 중 인터랙션을 유발할 수 있는 AC/제약이 있는가?" — 있으면 REJECT, 위임 규칙으로 변환 후 진행.

배경: 2026-07-20 pa-foundation에서 PO가 오너-결정 지점을 계약에 설계해 BLOCKED 6회·수동 재기동 8회 발생. 전부 계획 시점에 위임 규칙으로 명시 가능했던 결정들이었다. Ralph loop 컨셉의 핵심이므로 스킬 규칙 수준으로 박아 어떤 PO/사용자도 같은 실수를 반복하지 않게 해달라.

수용 기준: brainstorm/init 스킬 문서에 위 3항이 명시되고, 무인-완주 점검이 게이트로 동작(위반 PRD는 init 진행 전 반려).

## 요청 ② 캠페인 worktree 격리 옵션

- 공유 체크아웃에서는 동시 세션의 미커밋 작업이 전체-트리 게이트(typecheck·registry)를 오염시켜 루프가 자력으로 뚫을 수 없는 BLOCKED를 만든다 (2026-07-20 실측: 캠페인 외부 파일 14개가 pregate fail 유발).
- `--worktree` 플래그: run 시 리더가 전용 worktree(HEAD 기준 캠페인 브랜치) 생성, ROOT 전환. 종료 후 보존(감독자가 PR 머지), `clean --remove-worktree`로 정리. 스캐폴드는 리더가 복사, `pnpm install --frozen-lockfile` 1회.

수용 기준: 캠페인 실행 중 원본 체크아웃 편집이 캠페인 게이트에 영향 0. 기본값 경로는 바이트 동일(회귀 0).

## 요청 ③ BLOCKED 센티널 구조화 원인 필드 (P3)

- `cause: infra|contract_gap|defect` 필드 추가 — 감독자 자동 라우팅용. contract_gap(계약이 위임을 빠뜨림)은 감독자가 PRD를 고쳐 재기동해야 하는 신호로, 오늘 6회 전부 수동 분류했다.

## 참고

- ①의 워커측 표현: `--autonomous` 워커 프롬프트에 "PRD·계약·기존 관례 안에서 결정 가능한 것은 스스로 결정하고 근거 기록, blocked는 3사유만"을 함께 명시하면 계획 규칙과 실행 규칙이 짝이 된다.
