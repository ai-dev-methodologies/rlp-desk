# rlp-desk 문서 요청 (P3, docs) — tmux 모드 "리더 실행 위치"를 운영 계약으로 명문화 — 2026-07-21

요청자: tire-plletdata PO 세션 (오너 지시: "필요하면 규약에 넣는 게 맞다").

## 배경

- governance("Leader pane — deterministic shell loop")와 README("Inside tmux session → panes split in current window")는 리더가 tmux pane 안에서 도는 **구조**를 서술하지만, "**리더는 반드시 캠페인 tmux 세션 내 pane에서 실행되어야 한다 / detached·세션 밖 기동은 미지원**"이라는 **운영 계약 문구가 없다**.
- 실제로 우리 오퍼레이터(PO 세션)가 이 갭 때문에 리더를 tmux 밖 백그라운드로 30여 회 기동했고, 도구는 경고 없이 진행하다가(0.22.16 이전) 다중 클라이언트 환경에서 pane이 무관 세션 2곳으로 유출되는 실사고(회귀 보고 k ② 관찰)로 이어졌다. 0.22.19의 $TMUX_PANE 앵커링이 코드 수준에선 봉인했지만, 문서가 침묵하면 다음 오퍼레이터가 같은 갭을 밟는다.

## 요청 (전부 docs)

1. README tmux 모드 절 + governance에 **운영 계약 1문단**: "tmux 모드 리더는 캠페인 세션 내 pane에서 실행하는 것이 지원 형태다. 세션 밖/detached 기동은 미지원이며, 0.22.19+는 $TMUX_PANE 앵커링으로 이를 전제한다. $TMUX 부재 시 러너가 자체 세션을 만들고 그 안에서만 pane을 생성한다(또는 fail-fast — 현행 동작을 정본으로 서술)."
2. **오퍼레이터 패턴 노트**: 리더 pane은 로그 열람용이 아니라 pane-생성 앵커이므로, 평시 폭 1칸으로 접어도 무방하다. 단 **재기동 직전에는 split 가능한 폭으로 넓혀야 한다**(좁은 pane에서 split 실패 → 기동 실패). 권장: 기동 시 러너가 pane 폭을 검사해 부족하면 명확한 에러를 내는 것 (현재는 tmux 에러가 그대로 노출).
3. (선택) `--mode tmux` 도움말 한 줄에 동일 요지 반영.
4. **정본 레이아웃의 계약화 + 강제 (오너 지시 추가분)**: 아래 기하를 "권장"이 아니라 **정본 레이아웃 계약**으로 문서에 다이어그램으로 박고, 러너가 강제·복원하게 해달라.
   ```
   ┌────────────┬──┬──────────────┐
   │ 오퍼레이터   │리│  Worker      │  ← 리더에서 -h
   │ (요청 pane, │더│──────────────│
   │  Claude 등) │  │  Verifier    │  ← 워커에서 -v
   │            │  │──────────────│
   │            │  │  (Consensus) │  ← 검증자에서 -v
   └────────────┴──┴──────────────┘
   ```
   - 오퍼레이터 pane은 러너 소관 밖(존재 가정만). 리더 오른쪽에 워커/검증자/컨센서스가 **한 열 상하 스택** — 새 pane이 이 기하 밖(새 열·타 윈도우)에 생기면 러너가 스스로 교정하거나 명확한 에러.
   - 근거: 코드에는 이 순서가 이미 있으나(split -h/-v 체인) 계약·검증이 없어, 오퍼레이터 개입·pane 사망 후 재생성 경로에서 열이 늘어나거나 나란히 배치되는 드리프트가 실제 발생했다 (우리 세션에서 2회 — 3열 배치·가로 나란히 배치. 오너가 직접 지적).
   - 수용 기준: 기동·재생성·전 경로에서 pane 기하가 위 다이어그램과 일치. 불일치 시 silent 진행 금지.
